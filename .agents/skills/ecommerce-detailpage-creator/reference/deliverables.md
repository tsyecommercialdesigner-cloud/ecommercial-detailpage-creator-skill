# 交付规则与示例

用于检查策划、提示词或成品记录。模板由技能入口直接索引，需要文件化输出时才加载；不要求轻量咨询写完整台账。以下是 Markdown 业务约定，不是宿主 API 或 JSON Schema。

## 字段与状态契约

| 对象 | 必需内容与语义 | 检查动作与失败反馈 |
|---|---|---|
| 来源和事实 | 商品／型号、本次范围；S 编号、来源位置和参考用途；F 编号、值、来源、支持范围、状态 | 逐字段对照实际图片或确认记录；图像可见、文档／用户提供、待核实、冲突分别记录，缺证据不填值 |
| 顾虑映射 | Q 编号、关联 F 编号、买家问题、画面证据、有依据回答、待补内容 | 检查每个回答可追到对应事实；未知、无数据、不适用不能填为零或当成已确认 |
| 分屏卡 | P 编号与阅读顺序、主问题、F／Q 编号、标题／辅助文案／标签、画面证据、布局、共同约束、禁止推断、验收点 | 核对依据覆盖；同一外观／尺寸换标题不算新的购买判断；待补结构草案不能称完整可生成方案 |
| 提示词 | 本商品实图及保持项、单个顾虑、允许证据、逐字文字、布局、画幅和共同约束 | 与已确认方案逐屏对照；无法精确支持尺寸时记录实际能力，不猜工具参数或菜单名称 |
| 执行台账 | 批次与方案版本、屏号、实际工具／模型、有效授权、原始任务标识、状态、结果文件、实际尺寸、自检及返修记录 | 状态附实际操作证据；保存路径须存在、可打开且符合约定；未取得标识不能自行拼接 |
| 归档 | 本地位置或已获授权且实际写入的外部库位置、清单、用户认可状态 | 实际核对目标文件及旧版本保留；本地归档不等于外部上传，自检不等于用户认可 |

单位、尺寸、语言、阅读顺序按本次明确约定填写；没有平台要求不编造默认物理尺寸。输出位置由用户工作区及授权决定，不能向技能安装目录写业务结果。可用 商品标识/V1/P01-购买理由.png 命名；已有素材规范优先，同名冲突新增版本，不覆盖未知旧文件。

使用 待资料、待方案确认、提示词已交付、生成中、结果不明、部分完成、待用户验收、已验收归档 时，附支持状态的实际依据；无需新造状态 API。传输成功、任务成功、保存成功、画面合格分别记录。失败反馈包含屏号／字段、错误类别、违反条件、影响范围、已知副作用及可行动下一步，不能只写失败或 success。

## 空气炸锅的有界示例

这是合成演示，只有两项输入事实：本商品正面照片可见黑色机身、银色把手及前窗；用户确认烹饪时可通过该窗观察食物。未提供容量、功率、菜单和清洗说明。

事实 F01「前窗」对应 Q01「能否看到食物外观」。可交付一屏计划：

> 标题：食物状态，透窗看得见。画面：保持本商品前窗形状和位置，透窗可见食物；用标为“烹饪示意”的外观变化辅助说明。标签：可视窗口。禁止添加容量、温控、预约、健康承诺和减少失败率的量化结论。

这只能形成有依据的一屏计划及其提示词；要形成六屏，需要补充其他真实信息或提出待核实结构草案。不能照抄教程的 6L、8 种预设或整机可冲洗。

## 正常、反例与恢复

- 输入实图及本型号确认参数，用户要求先做六屏方案：交付事实表、顾虑表、P01–P06 卡片及待确认项；生成次数为零。
- 用户只要一张 SKU 白底图：转到单图能力，保留该任务输入，不额外展开多屏策划。
- 用户确认方案但工具不可用：交付方案和逐屏提示词，状态为提示词已交付，明确尚无成品。
- P01/P02 已保存，P03 超时且有任务号，P04–P06 未提交：先查 P03；不重提 P01–P03。按授权可继续 P04–P06，并交付逐屏状态，不能称全部完成。
- P02 乱码，其余图通过：定位文字问题、保留原文件，按授权局部修复并重新核对该屏与整套一致性；不重新生成整套。
