# Agent Skills 手册与交付编写规范

本指南规定消费项目 README、MANUAL 和安装／分发说明应包含的内容；设计、评测与 CI/CD 细则见[工程指南](ENGINEERING-GUIDE.md)。具体项目填入真实版本、路径、入口和检查结果；未实现或未验证的能力不能写成可用。编写说明不授权安装宿主、改用户配置或调用真实业务。

## 1. 范围与实际参数

README 提供项目目的、技能清单、适用范围、最短可用路径及手册链接；复杂步骤集中在 MANUAL，避免重复维护。先从实际仓库和发行记录建立参数表，不继承模板维护仓库的身份或某个示例的业务字段。

| 参数 | 需要说明的事实 |
|---|---|
| 来源与版本 | 实际仓库／发行地址、目标版本与完整提交 SHA、校验方式和所需访问授权；地址不含令牌。 |
| 技能与布局 | 技能目录、`name`、单技能／技能库／插件的关系，以及随包引用的脚本、资料和 assets。 |
| 目标环境 | 宿主及版本、终端／IDE／云端等会话类型、模型、OS 与必要运行时；明确已验证组合。 |
| 安装与作用域 | 源码路径、安装根、技能根、用户／仓库等作用域、发现路径及复制／链接／安装器／插件方式。 |
| 工具与配置 | 必需和可选依赖、工具真实 ID、网络、秘密字段及安全配置渠道；无依赖或凭据时明确不需要。 |
| 成功标准 | 安装后发现、选用、执行、输出核验及失败反馈的实际检查入口与预期。 |

明确角色是技能维护者、安装使用者，还是外部服务维护者；仅使用技能的人不应被要求执行无关的后端部署。通用规范可以说明参数填写要求，项目最终手册中的命令必须可用于其真实发行版本。

## 2. 获取、安装与发现

- 使用已通过规定检查的真实发布版本；没有标签时明确目标完整 SHA 及验证状态。不在日常调用时自动跟随默认分支更新。
- 安装前核对来源、版本与内容，保留既有目录和用户配置。发现同名技能、目标路径已存在或本地有改动时先比较差异，不能默认覆盖；凭据使用用户已有的安全认证机制。
- 区分源码布局和宿主发现位置。项目 `skills/` 目录不保证自动被任何宿主扫描，须写出所选版本的实际安装过程、作用域和加载／刷新操作。

- 只保留项目实际支持的分支。按支持的 OS／Shell 提供完整步骤，正确处理引号、路径与退出状态；不规定统一 Windows 盘符，不把本机路径直接当作云端可读路径。
- 带脚本时在准备阶段安装锁定依赖及必要构建，给出工作目录、运行时与真实命令；纯指令 Skill 省略这些步骤。不同宿主的执行环境可能不同，不能以开发机有依赖推断安装端可运行。
- 验证宿主确实发现正确来源和版本，再进行调用检查。文件存在、元数据解析成功和宿主可见分别报告；链接安装还需验证目标可达、发布可移植性及卸载边界。

### 2.1 Skills 存放位置与生效范围

手册分别列出源码仓库、宿主扫描的技能父目录和每个技能的根目录，说明采用用户级还是项目级安装。下表覆盖本地 Claude Code、Codex 和 DeepSeek Harness（DSH），不列企业托管级、管理员级或系统内置目录；插件分发另按第 2.3 节说明。路径是核对基线，具体手册须记录所用宿主／提供方版本、配置覆盖与已验证的会话类型。

| 宿主 | 用户级技能父目录 | 项目级技能父目录 | 生效范围与发现规则 |
|---|---|---|---|
| Claude Code | `~/.claude/skills/` | `<project_root>/.claude/skills/`；适用版本也支持子目录中的 `.claude/skills/` | 用户级供本机该用户跨项目使用，项目级随仓库共享。启动目录及向仓库根的祖先目录参与发现；启动位置下方的技能何时加载按版本及文件访问行为核对，不宣称启动即递归加载整个仓库。 |
| Codex | `~/.agents/skills/` | 从当前启动目录到仓库根各层的 `.agents/skills/`，例如 `<repo_root>/.agents/skills/` | 仓库内从当前工作目录向上逐级发现，不等于向下扫描所有兄弟子项目。用户级用于个人跨仓库复用；`agents/openai.yaml` 的调用策略及工具依赖按目标版本说明。 |
| DeepSeek Harness | `<dshHome>/skills/` 和 `<agentsHome>/skills/`；默认分别为 `~/.dsh/skills/`、`~/.agents/skills/` | `<projectRoot>/.dsh/skills/` 和 `<projectRoot>/.agents/skills/` | 使用本地文件系统技能提供方时适用。`projectRoot` 为当前工作目录向上最近包含 `.git` 的目录，未找到时为当前工作目录；不是 Codex 的逐层项目技能目录扫描。 |

- `~` 表示实际运行宿主的用户主目录。Windows 原生环境通常对应用户配置文件目录，WSL、容器、SSH 与远端会话使用各自的主目录；不能把 Windows 客户端磁盘路径当成远端可读位置。文档路径使用 `/`，实际命令按 Shell 展开并正确引用，不假定 JSON/YAML 中的 `~` 或环境变量会自动展开。
- 团队共享技能应从约定 Git 基线取得，按所选项目级发现目录安装；用户级目录用于个人跨项目复用，不因位于用户目录就保证不被同步或提交。通用源码 `skills/` 本身不是三宿主共同的自动发现目录，手册须给出复制完整技能包、链接或安装器映射的真实步骤。
- 同时支持 Codex 和 DSH 时，可选择两者均支持的 `.agents/skills/` 作为共享来源；但需分别验证项目根、扫描范围、元数据和资源执行兼容性。Claude Code 可通过其发现位置的受支持链接或安装映射复用同一包，不能假定它自动扫描 `.agents/skills/`；避免维护多份独立正文。

### 2.2 技能包布局与目录验收

跨宿主复用默认采用目录包；技能根目录中入口必须命名为 `SKILL.md`，大小写准确。以下约束单个 Skill 开发产物，不约束开发项目的仓库布局；目录及命名细则见[工程指南第 2.1 节](ENGINEERING-GUIDE.md#21-产物目录一级引用与命名)。具体手册用真实名称替换，并只保留实际交付的可选资源：

```text
<skills_dir>/
└── <skill_name>/
    ├── SKILL.md
    ├── reference/    # 可选：按功能域平铺规则、契约、辅助文档
    ├── scripts/      # 可选：已验证的执行脚本
    └── assets/       # 可选：模板及必要资源
```

`<skills_dir>` 是第 2.1 节选定的技能父目录，`<skill_name>/` 才是该 Skill 的根目录；本模板要求目录名与 frontmatter `name` 一致。不能把 `SKILL.md` 直接放在技能父目录，也不额外套一层发行包同名目录；宿主扩展的其他格式单独说明，不作为跨宿主通用布局。

- DSH 本地提供方支持父目录下直属的目录包和扁平 `<name>.md`，不支持递归发现任意层级的 `**/SKILL.md`。兼容三宿主时仍使用上述目录包，不能将 `skills/category/<skill_name>/SKILL.md` 误认为一定会被发现；技能内资源子目录与技能发现层级是两回事。
- 依本项目工程约定，资源采用一级子目录，`SKILL.md` 用相对路径直接指向目标，引用跳转不超过一级；大量知识按功能域拆入 `reference/`，写明按需读取条件，不以辅助文档串联更多文档来取得关键指令。此为产物组织要求；脚本入口、权限及解析基准按工程指南核对，不照搬“所有宿主都在 Linux 容器运行”或统一 `chmod` 要求。
- 安装后核对实际生效的技能名称、来源路径和版本，确认引用资源随包到达且能从实际会话访问；跨平台验证大小写、空格和中文路径。目录可见不保证脚本已具备运行依赖或权限，源码布局检查不能代替宿主发现与调用验收。

### 2.3 DSH 配置、插件与同名处理

- DSH 须确认实际组合中已启用 `@deepseek-ai/dsh-skill` 注册表及 `@deepseek-ai/dsh-skill-filesystem` 本地提供方；仅创建目录不保证可见。`dshHome` 默认取 `DSH_HOME` 或 `~/.dsh`，`agentsHome` 默认取 `DSH_AGENTS_HOME` 或 `~/.agents`；显式配置改变根目录时，手册填写实际解析位置，不机械套用默认值。
- DSH 可通过该提供方的 `customSkillDirs` 增加技能父目录；`includeDefaultRoots: false` 会关闭默认项目／用户根的发现。必须说明自定义目录、配置归属与作用域，不能把 profile 名称直接当成技能目录。原生 DSH、桌面端或其他集成分别核对宿主运行位置、会话 cwd 及插件组合，不假定同一客户端用户目录必然共享。
- 在核对的 DSH 实现中，同一注册层内较小 rank 优先：项目 `.dsh/skills` → 项目 `.agents/skills` → 自定义目录 → 用户 DSH 目录 → 用户 agents 目录；跨注册层先按观察 scope 选择最近层。不要把这个顺序推广到其他宿主，或声称项目目录能覆盖所有 agent preset 的技能。
- Codex 同名技能不会合并，可能同时出现在选择器；Claude Code 的个人／项目及嵌套同名行为按实际版本核对，插件技能以 `/plugin-name:skill-name` 等产品命名空间区分；DSH 按实际提供方与 scope 裁决。手册应教成员确认生效来源，不照搬原文的一条跨宿主覆盖优先级链，也不通过删除其他技能解决冲突。
- 插件技能由相应安装器、插件清单或提供方管理，不将缓存中的真实物理路径当作稳定的手工安装目录。Claude Code 插件包使用 `<plugin_root>/skills/<skill_name>/SKILL.md`；Codex 插件与 DSH 随包／其他提供方按各自版本的实际清单和加载机制说明，不能统一写成某个 `~/.claude/plugins/` 路径。
- 分别说明宿主的目录监视、重新发现或重启方式。DSH 默认启用监视时，技能增删／改名或入口元数据变化可刷新目录，正文在加载时重新读取；关闭监视或使用不同提供方时按实际行为验证。Claude Code 和 Codex 使用各自支持的刷新方式，不能因一个客户端自动刷新就宣称全部支持热加载。

## 3. 配置、资源与工具

- 说明技能根、脚本工作目录及用户输入输出位置的区别；明确相对路径解析、文件访问范围、覆盖策略和结果保存位置。用户从不同工作目录发起任务时仍应取得同一份必需资源。
- 给出实际工具名称、来源、用途、权限及必需性，说明如何检查连接；工具声明或可选适配文件的存在不代表已连接成功。缺少必需能力时提供诊断，不能伪造“已完成”。
- 凭据按实际宿主或脚本机制配置，解释字段、读取来源、优先级、缺失／非法值和生效方式；保留用户已有设置。不要求在聊天、命令行、共享 YAML 或日志中填写真实秘密，也不假定所有产品会展开 `${VAR}`。
- 只交付无秘密的共享模板；如使用 `.env.example`，秘密字段留空。项目不需要密钥时不要添加认证步骤；本地文件不自动同步到云端，后端认证也不自动成为宿主认证。
- 指出读写、通知、发布和收费等实际副作用，按既有授权与平台策略操作。说明权限限制与失败反馈，不承诺 Skill 文本或 `allowed-tools` 能独立提供隔离。

## 4. 调用示例与可用性验证

每个技能至少说明目标、适用／不适用情况、输入准备、执行过程、预期产物与验证方法。展示正常任务、相邻但不适用任务和信息不足／可恢复失败任务；示例与实现、契约及评测场景保持一致。

- 提供目标宿主实际支持的显式调用方式和代表性的自然语言请求，验证正确来源／版本被选用；自动选择能力需另测漏选、误选和相邻技能消歧。
- 需要脚本时给出实际入口、参数、超时、退出码及期望输出；有输出契约时核对字段和含义。例子不依赖发行包外的维护者私有文件、全局依赖或临时状态。
- 核对过程中的资料读取、必要步骤、结果正确性与失败反馈。格式检查、替身测试、实际宿主验证及真实业务验证分开记录；未授权的写入／收费动作不作为默认安装检查。
- 将验收标识关联到证据，记录日期、版本、宿主／模型／平台、命令或请求、预期与实际结果及未覆盖项；秘密和私有输入脱敏。仅有截图、进程或退出码不能替代目标行为断言。

## 5. 排障、升级、回滚与卸载

| 问题 | 首先检查 | 不应采用的通用修法 |
|---|---|---|
| 未发现或发现旧版本 | 安装位置、作用域、目录／元数据、宿主版本、重复来源与刷新状态。 | 全量清空用户技能或共享配置。 |
| 误选／漏选 | `description`、调用策略、名称冲突、任务边界及实际加载信息。 | 擅自取消边界或假定显式成功证明隐式有效。 |
| 资源／脚本失败 | 实际包内容、路径基准、工作目录、权限、锁定依赖及构建入口。 | 删锁、浮动升级、临时全局安装或从无关目录借文件。 |
| 工具／网络／认证失败 | 工具存在性、连接、目标访问、绑定名称／状态与实际权限。 | 打印秘密、绕过验证或无依据重复索取凭据。 |
| 输出不合格或部分成功 | 输入与契约、执行证据、失败原因、副作用和量规。 | 降低断言、伪装成功或盲目重试写入。 |

升级前记录当前来源与版本，检查本地修改，备份必要的私有配置并保护访问权限；取得已验证目标版本后更新完整技能包及适用依赖，重新发现和验证。保留用户配置、数据与自定义内容，新增字段明确合并，不用整目录清空或强制覆盖升级。

回滚恢复已记录的完整旧版本、匹配资源与依赖，并按目标宿主复验；说明数据／契约迁移限制，源码回退不保证业务数据可逆。失败安装的残留与原有可用版本明确区分，不能悄悄以旧行为冒充新版本成功。

卸载仅移除本技能拥有的安装文件、链接或注册项，使用产品支持的机制；共享依赖、其他技能、用户配置与结果数据按所有权保留。给出可见性复查方法，不把删除用户目录作为默认卸载。

## 6. 发行内容与交付验证

源码仓库与技能发行包分别验收，Git 忽略规则不等于发布清单；发布流程遵从[工程指南](ENGINEERING-GUIDE.md#6-cicd-与版本交付)。不强制项目采用某一种归档或插件渠道，按目标产品定义布局。

| 内容 | 交付要求 |
|---|---|
| 技能入口及运行引用 | 包含 `SKILL.md` 和全部必需脚本、参考资料、assets、许可证；适用运行声明／锁、构建产物及产品适配文件均可取得。 |
| 仓库开发资料 | 测试、评测集、CI 和规范保留在源码仓库；仅当运行引用或产品要求时进入技能包。不能因目录名为 docs／`.agents`／`.claude` 就盲目排除必需文件。 |
| 发行追溯 | 版本、完整提交、内容清单、校验摘要、变更与兼容说明、安装及必要评测结果。插件清单另按产品核对。 |
| 禁入内容 | 真实秘密、认证与会话、私有输入、原始轨迹、本机配置、无关依赖和缓存；不能仅以 Git 状态干净证明包无秘密。 |

在独立临时目录中从真实目标版本取得发行内容，检查路径越界、重复项、必需引用及适用权限，完成准备、宿主发现、调用和代表性结果验证。使用隔离的缓存／环境，避免借用开发机、祖先目录或全局依赖；未能验证的平台和功能如实列出。

用无真实权限的测试配置验证升级／回滚／卸载的保留行为，不操作用户真实文件。最终分别报告通过、失败、不适用和未验证项；本规范维护仓库的文档检查不代表消费项目已通过这些交付检查。
