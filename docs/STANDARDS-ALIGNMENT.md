## 复用价值与最小基线

目标使用者是需要反复为不同商品策划多屏详情页的成员。可复用部分是“事实 → 顾虑 → 画面证据 → 方案 → 结果核验”，收益在于保持事实与授权边界、减少凑屏和未知任务重提；实际使用频率、节约时长和 ROI 尚无观测，不编造数字。与单图编辑／网站开发保持边界，不另建重叠 Skill，不新增业务运行依赖或配套 Server。

方法依据仍是七张 SOP 的事实、顾虑、分屏与验收；八个策划动作按商品证据选用，六屏只是默认示例。画面风格、具体构图和商业视觉判断保留探索与用户验收空间，不把示例参数或未验证路线固化成产品承诺。

先复验旧版最小基线，再实施迁移：

- 原结构／链接、34 项旧测试及旧证据指纹通过。
- Codex CLI 0.163.0 的真实 App Server `skills/list` 返回唯一、enabled、scope=repo 的目标技能，名称、101 字符描述及实际入口路径正确，解析错误为空。
- 自然语言六屏策划 S01、单图近邻 S02、显式策划分别三次通过语义与实际轨迹核验。首轮显式试验有两条没有可观察的正文读取，未记为加载通过；补充明确的正文读取要求后另跑完整三次，保留首轮记录，不推测宿主隐藏注入行为。

此 MVP 是真实 CLI 上的**合成资料策划闭环**，不替代真实商品、收费服务或商业画面验收。没有扩展正式安装目标、收费工具或批量宿主适配。

发现的评测问题按原 expected／critical 修正，未改 `cases.json` 的请求、判据或重复次数：

1. 原生近邻曾为 2/3：评分器把已保存编辑结果的后续局部修复误报为越权。现按实际授权原图与已保存派生链核对，其他图片仍拒绝；新增合法派生／无关任务／其他图片回归。
2. 完整组旧 tag 曾为 47/48：B07-r3 已生成、保存、看图并报告缺陷后询问返修，被裁判扩大解释成“重复要授权而不执行”。明确不得增加额外返修或完美 mock 画面要求；新 `calibrated` tag 对全部 16 组重新评分，48/48，不只挑失败样本重判。
3. 安全扫描原先对未暂存迁移留下的删除路径报文件不存在。仅排除 Git 已报告且仍缺失的删除项，新文件及重新出现文件继续扫描；不靠暂存或降低秘密检查绕过。CI 子日志与报告保留最终结果，观察到的原失败另记入归档。

旧判分、诊断批次、最终判分及源码均保留，原始裁判输出未手改。[公共证据](../evals/evidence.json) 是维护者审计后的脱敏快照，CI 校验版本和完整性，不是模型重放、独立签名或真实服务认证。原 [schema 1 基线](../evals/baseline-evidence.json) 与 Git 基线中的旧证据字节完全一致。
