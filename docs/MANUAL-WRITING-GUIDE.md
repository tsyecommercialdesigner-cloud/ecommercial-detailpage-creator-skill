# Agent Skills 手册与交付编写规范

本指南规定消费项目 README、MANUAL 和安装／分发说明应包含的内容；设计、评测与 CI/CD 细则见[工程指南](ENGINEERING-GUIDE.md)。具体项目填入真实版本、路径、入口和检查结果；未实现或未验证的能力不能写成可用。编写说明不授权安装宿主、改用户配置或调用真实业务。

## 1. 范围与实际参数

README 提供项目目的、技能清单、适用范围、最短可用路径及手册链接；复杂步骤集中在 MANUAL，避免重复维护。先从实际仓库和发行记录建立参数表，不继承模板维护仓库的身份或某个示例的业务字段。

| 参数 | 需要说明的事实 |
|---|---|
| 来源与版本 | 实际仓库／发行地址、目标版本与完整提交 SHA、校验方式和所需访问授权；地址不含令牌。 |
| 技能与布局 | 技能目录、`name`、单技能／技能库／插件的关系，以及随包引用的脚本、资料和 assets。 |
| 目标环境 | 宿主及版本、终端／IDE／云端等会话类型、模型、OS 与必要运行时；明确已验证组合。 |
| 安装与作用域 | 源码路径、安装根、技能根、用户／仓库等作用域、发现路径及复制／链接／安装器／插件方式。 |
| 工具与配置 | 必需和可选依赖、工具真实 ID、网络、秘密字段及安全配置渠道；无依赖或凭据时明确不需要。 |
| 成功标准 | 安装后发现、选用、执行、输出核验及失败反馈的实际检查入口与预期。 |

明确角色是技能维护者、安装使用者，还是外部服务维护者；仅使用技能的人不应被要求执行无关的后端部署。通用规范可以说明参数填写要求，项目最终手册中的命令必须可用于其真实发行版本。

## 2. 获取、安装与发现

- 使用已通过规定检查的真实发布版本；没有标签时明确目标完整 SHA 及验证状态。不在日常调用时自动跟随默认分支更新。
- 安装前核对来源、版本与内容，保留既有目录和用户配置。发现同名技能、目标路径已存在或本地有改动时先比较差异，不能默认覆盖；凭据使用用户已有的安全认证机制。
- 区分源码布局和宿主发现位置。项目 `skills/` 目录不保证自动被任何宿主扫描，须写出所选版本的实际安装过程、作用域和加载／刷新操作。

| 宿主分支 | 文档需要核对的内容 |
|---|---|
| Codex | 本地仓库与用户作用域的 `.agents/skills/` 等位置、发现范围、显式／隐式调用、同名处理及必要刷新；`agents/openai.yaml` 的策略或工具依赖按目标版本说明。 |
| Claude Code | 本地 `.claude/skills/` 等位置、作用域、`/name` 与按描述调用、产品扩展和刷新；本地、云端及账户同步入口分别核对。 |
| 其他产品／插件 | 实际产品、版本、包格式、上传／安装入口、资源执行支持、权限与可见范围；没有验证依据就不声明支持。 |

- 只保留项目实际支持的分支。按支持的 OS／Shell 提供完整步骤，正确处理引号、路径与退出状态；不规定统一 Windows 盘符，不把本机路径直接当作云端可读路径。
- 带脚本时在准备阶段安装锁定依赖及必要构建，给出工作目录、运行时与真实命令；纯指令 Skill 省略这些步骤。不同宿主的执行环境可能不同，不能以开发机有依赖推断安装端可运行。
- 验证宿主确实发现正确来源和版本，再进行调用检查。文件存在、元数据解析成功和宿主可见分别报告；链接安装还需验证目标可达、发布可移植性及卸载边界。

## 3. 配置、资源与工具

- 说明技能根、脚本工作目录及用户输入输出位置的区别；明确相对路径解析、文件访问范围、覆盖策略和结果保存位置。用户从不同工作目录发起任务时仍应取得同一份必需资源。
- 给出实际工具名称、来源、用途、权限及必需性，说明如何检查连接；工具声明或可选适配文件的存在不代表已连接成功。缺少必需能力时提供诊断，不能伪造“已完成”。
- 凭据按实际宿主或脚本机制配置，解释字段、读取来源、优先级、缺失／非法值和生效方式；保留用户已有设置。不要求在聊天、命令行、共享 YAML 或日志中填写真实秘密，也不假定所有产品会展开 `${VAR}`。
- 只交付无秘密的共享模板；如使用 `.env.example`，秘密字段留空。项目不需要密钥时不要添加认证步骤；本地文件不自动同步到云端，后端认证也不自动成为宿主认证。
- 指出读写、通知、发布和收费等实际副作用，按既有授权与平台策略操作。说明权限限制与失败反馈，不承诺 Skill 文本或 `allowed-tools` 能独立提供隔离。

## 4. 调用示例与可用性验证

每个技能至少说明目标、适用／不适用情况、输入准备、执行过程、预期产物与验证方法。展示正常任务、相邻但不适用任务和信息不足／可恢复失败任务；示例与实现、契约及评测场景保持一致。

- 提供目标宿主实际支持的显式调用方式和代表性的自然语言请求，验证正确来源／版本被选用；自动选择能力需另测漏选、误选和相邻技能消歧。
- 需要脚本时给出实际入口、参数、超时、退出码及期望输出；有输出契约时核对字段和含义。例子不依赖发行包外的维护者私有文件、全局依赖或临时状态。
- 核对过程中的资料读取、必要步骤、结果正确性与失败反馈。格式检查、替身测试、实际宿主验证及真实业务验证分开记录；未授权的写入／收费动作不作为默认安装检查。
- 将验收标识关联到证据，记录日期、版本、宿主／模型／平台、命令或请求、预期与实际结果及未覆盖项；秘密和私有输入脱敏。仅有截图、进程或退出码不能替代目标行为断言。

## 5. 排障、升级、回滚与卸载

| 问题 | 首先检查 | 不应采用的通用修法 |
|---|---|---|
| 未发现或发现旧版本 | 安装位置、作用域、目录／元数据、宿主版本、重复来源与刷新状态。 | 全量清空用户技能或共享配置。 |
| 误选／漏选 | `description`、调用策略、名称冲突、任务边界及实际加载信息。 | 擅自取消边界或假定显式成功证明隐式有效。 |
| 资源／脚本失败 | 实际包内容、路径基准、工作目录、权限、锁定依赖及构建入口。 | 删锁、浮动升级、临时全局安装或从无关目录借文件。 |
| 工具／网络／认证失败 | 工具存在性、连接、目标访问、绑定名称／状态与实际权限。 | 打印秘密、绕过验证或无依据重复索取凭据。 |
| 输出不合格或部分成功 | 输入与契约、执行证据、失败原因、副作用和量规。 | 降低断言、伪装成功或盲目重试写入。 |

升级前记录当前来源与版本，检查本地修改，备份必要的私有配置并保护访问权限；取得已验证目标版本后更新完整技能包及适用依赖，重新发现和验证。保留用户配置、数据与自定义内容，新增字段明确合并，不用整目录清空或强制覆盖升级。

回滚恢复已记录的完整旧版本、匹配资源与依赖，并按目标宿主复验；说明数据／契约迁移限制，源码回退不保证业务数据可逆。失败安装的残留与原有可用版本明确区分，不能悄悄以旧行为冒充新版本成功。

卸载仅移除本技能拥有的安装文件、链接或注册项，使用产品支持的机制；共享依赖、其他技能、用户配置与结果数据按所有权保留。给出可见性复查方法，不把删除用户目录作为默认卸载。

## 6. 发行内容与交付验证

源码仓库与技能发行包分别验收，Git 忽略规则不等于发布清单；发布流程遵从[工程指南](ENGINEERING-GUIDE.md#6-cicd-与版本交付)。不强制项目采用某一种归档或插件渠道，按目标产品定义布局。

| 内容 | 交付要求 |
|---|---|
| 技能入口及运行引用 | 包含 `SKILL.md` 和全部必需脚本、参考资料、assets、许可证；适用运行声明／锁、构建产物及产品适配文件均可取得。 |
| 仓库开发资料 | 测试、评测集、CI 和规范保留在源码仓库；仅当运行引用或产品要求时进入技能包。不能因目录名为 docs／`.agents`／`.claude` 就盲目排除必需文件。 |
| 发行追溯 | 版本、完整提交、内容清单、校验摘要、变更与兼容说明、安装及必要评测结果。插件清单另按产品核对。 |
| 禁入内容 | 真实秘密、认证与会话、私有输入、原始轨迹、本机配置、无关依赖和缓存；不能仅以 Git 状态干净证明包无秘密。 |

在独立临时目录中从真实目标版本取得发行内容，检查路径越界、重复项、必需引用及适用权限，完成准备、宿主发现、调用和代表性结果验证。使用隔离的缓存／环境，避免借用开发机、祖先目录或全局依赖；未能验证的平台和功能如实列出。

用无真实权限的测试配置验证升级／回滚／卸载的保留行为，不操作用户真实文件。最终分别报告通过、失败、不适用和未验证项；本规范维护仓库的文档检查不代表消费项目已通过这些交付检查。
