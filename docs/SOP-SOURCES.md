## 还原后的顺序

1. 输入本商品图和参数，确认任务范围。
2. 提取可证实事实，列出缺失、冲突和禁止推断。
3. 事实翻译为买家顾虑，匹配画面证据。
4. 分屏策划：先首屏，再关键功能证据、清洗、参数／容量、菜单及末屏收束；逐屏写标题、标签和布局。
5. 将每屏任务转成完整提示词，在具体方案确认及生成授权范围内出图。
6. 逐图和整套核对，返修后交用户视觉判断，合格归档。

运行入口将以上压缩为五阶段：1 事实（含输入准备），2 顾虑，3 分屏，4 绘图任务，5 验收归档。详细八个策划动作和六屏阅读顺序见技能内 `reference/workflow.md`。

## 原文、整理与执行补充的界限

- 原图明确给出：先事实后卖点；每屏解决一个问题；标题、标签、画面证据；完整成品图；检查乱码、空白和虚假承诺；合格素材入库。
- 目录／示例可支持的整理：首屏理由、窗口证据、清洗、参数判断、菜单选择和最后收束。当前没有第 5–8 动作各自独立的详细正文图片，不声称已读到这些单页的完整操作说明。
- 六屏排法采用总览示例：首屏、窗口、清洗、容量、菜单、购买判断。参数策划在菜单前；参数汇总与整套总结合并为第六屏，这是处理两套编号的整理选择，不是原图明确规定所有商品只能六屏。
- 为可靠执行补充：来源／事实编号、方案版本、生成前确认、收费与外发授权、未知结果不重提、部分失败恢复、工具缺失时交提示词、文件清单和跨品类替换规则。这些是项目工程化约定，不能冒称教程原文。
- 原图示例中有 6L、1700W、8 个预设、约 4kg，以及温控、计时等标签。它们不证明用户未来商品的参数。示例里「不粘涂层」「安全保护」「实时火候」「省时省力」「少开盖减少热量流失」等，也必须为实际商品补充依据；本 Skill 不直接继承为通用事实。
- 食物颜色变化是说明画面的思路，不能当作精确熟度、食品安全、烹饪时间或减少失败率的验证。实际图和参数与教程示例冲突时，以核实的本商品资料为准。
